## Semantic adaptation in each feature commit

1. **Shard isolation and managed API keys.** Both the old local branch and new official branch used auth snapshot version 28 for different fields. Version 29 now requires both the shard scope and official `ForceOpenAIUltrafast`; versions 27/28 are evicted. Combined JSON roundtrip and scheduler tests retain the hydrated-group fast path, with no extra group read per request. Preserve official asynchronous usage loading in managed keys. Combine Ent schemas before regenerating rather than selecting one generated conflict side; new official handler constructor tests receive the shard dependency. Consolidate the official new orphan/tool-schema/heap subprocess fixtures into the existing allocation helper, retaining coverage forwarding, the official no-janitor resolver fixture, final `KeepAlive`, 20,000 models and the 8 MiB ceiling.
2. **Subscription balance fallback.** Explicit `BillingSource` remains selected at admission and travels through handler snapshots, asynchronous billing, limits and inflight reservations. Preserve official `applyCtx` and the independent post-commit cache deadline. A real regression failure exposed two local account fixtures missing `StatusActive` / `Schedulable`: official scheduler snapshots now correctly exclude those fixtures. Correct only the fixture state, not production filtering or assertions. Recharge-format and subscription-helper imports coexist.
3. **Client bootstrap.** No new structural change is required. Keep the read-only bootstrap API; only an explicitly unconfigured default group becomes `needs_setup`, while database errors and cancellation retain their error chain. The feature patch remains equivalent to the original.
4. **Matcha package registry and metering.** Official `UsageBillingLaneCombiner` introduces concurrent `ApplyBatch`; the old single-`Apply` insertion point alone would omit package charges. Single and batch settlement now derive package amounts after dedup claim, within the same transaction as usage, revenue, balance, subscription and quotas. A positive package fee creates a transaction-local command copy; caller amounts remain unchanged when a batch rolls back and falls back to single application. Only the first derived command copies the batch slice; ordinary commands keep the existing path. Both settlement forms return actual applied amounts for cache/quota/notification updates. Preserve official batch grouping, lock ordering, worker lifecycle and separate cache timeout instead of bypassing batching.
5. **Shared shard accounts and administration.** Preserve parent-group membership checks, transactional shared/exclusive writers and last-live-user cleanup. Combine regenerated shared Account/Group/Shard edges with the official schema. Keep complete picker pagination, batch selection/deselection and viewport-bound scrolling. No scheduler tier or protocol-policy rewrite is introduced.
6. **Theme and persistent layout.** Preserve official active-query loading, quota/query controls, model passthrough filters, Fast/Ultrafast settings, pricing/cache buckets and recharge precision. Reuse existing theme tokens for newly added official controls and the sticky settings save dock; do not add a parallel palette. Preserve the official payment formatter while retaining single ownership of the persistent layout. The official Fast-copy test fails on the untouched official ref (3 pass / 1 fail); assert the current documented entitlement/fallback distinction instead of a removed `service_tier=ultrafast` substring. Add a save-dock theme regression. Desktop-login and route lifecycle contracts remain covered.

## Renewal failure diagnosis and remaining red result

- The first default full run failed `TestInflightReservation_RenewalKeepsStreamingReservationAlive`, which uses a 1-second TTL and a 2.5-second streaming wait. Isolated original candidate and untouched official tests each passed 7 and failed 1 in 8 repetitions. Matching symptoms alone are not causal proof.
- The production Redis scripts are identical to official; the renewal loop is also unchanged. An external trace of the original candidate test captured a successful renewal at wall `1795081256466`, expiring at `1795081257466`; the next tick arrived at wall `1795081258529` with negligible ticker lateness, so the script correctly refused an already-expired reservation. The next reservation then succeeded, directly explaining the assertion failure in that traced run.
- A further external dual-clock trace retained the original test assertions and failed 3 of 32 repetitions. Each failed renewal coincided with an independently sampled wall/monotonic discontinuity: wall time advanced 2.109/3.065/3.049 seconds between nominal 333 ms ticks, while monotonic time advanced 333 ms; Redis calls took under 1 ms. The captured script read an expired score and returned false. The matching independently sampled skew differs by less than 1 microsecond, separating the observed clock jump from scheduler or Redis latency. Details and attribution boundaries are in `renewal-diagnosis/findings.json`.
- Independent wall/monotonic sampling observed multi-second wall-clock jumps across roughly 20 ms of monotonic time. The single full default recheck records seven forward jumps of approximately 2.46-2.74 seconds, including a jump during the failing renewal window. This full recheck has no internal per-request trace, so its exact internal path is not independently proven. Timer cadence and absolute lease expiry therefore disagree in this WSL environment.
- Controlled miniredis and independent real-Redis checks confirm that normal renewal retains a live lease and delayed renewal never resurrects an expired lease. This does not prove every historical failure has the same cause; the first uninstrumented full run has no per-renewal trace.
- No production lease semantics, TTL, threshold, sleep, test assertion or skip condition is changed to obtain a green run. The default-suite failure remains a visible acceptance limitation; full unit passing does not replace it. Evidence is under `renewal-diagnosis/` and `final-default-recheck-*`.
